# 验证记录

日期：2026-10-01。版本：0.1.0。

## 已完成

- 生成器自检通过：多页画框、frame 引用、唯一 ID、中英文及显式换行、页内编组与跨页隔离、负方向箭头边界、越界和无效数字拒绝。
- 从通用布局 JSON 成功生成三页示例：36 个原生元素（含画框与背景），全部画框 1080×1440，无图片元素。
- YAML 使用 Ruby 标准 YAML 解析器解析通过；检查 Skill 名称、描述、支持字段和默认调用提示。
- Markdown 相对引用检查通过；公开包扫描未发现制作环境绝对路径、原创作者姓名、凭据字段或脚手架占位内容。包中没有摄像头截图、字体或第三方素材。
- 人工检查指令分支：方向未确认时先确认；已有选择不重复问；白板变更后同步稿件；稿件未确认时不能填提词器；已确认时完成网页填写；已有无关稿件时询问覆盖；浏览器失败时明确未完成；不得代替用户自动开始录制。

## 既有真实操作证据的范围

封装前的六页样例已在 Excalicord 实际导入，识别六个原生 frame，点击页码定位切换；文字进入原生编辑状态；录制比例 3:4 选中；六段口播稿成功填入可编辑提词器并读回。

这是本 Skill 所依据的工作流程验证，不等于全新安装环境端到端测试通过。通用三页示例完成了生成与结构校验，尚未单独在网页重新导入验收。

## 尚未验证

- 全新用户安装后，由另一助手从素材开始独立完成所有确认、制作、导入和提词器填入。
- 不同浏览器、不同 AI 宿主及未来 Excalicord 版本的兼容性。
- 实际录制中的切页、声音、人像位置、视频导出尺寸。
- 关闭网页后提词器稿件能否持久保留。

官方 quick_validate.py 已尝试运行，当前 Python 环境缺少 PyYAML，未运行完成；使用系统 Ruby YAML 解析和结构检查替代。没有为此安装用户环境依赖。可在已有 PyYAML 的开发环境补跑官方校验器。

## 发布前人工试用

在一个新会话中使用 README 的示例提示，先确认方向和分页，导入示例后修改一句文字，再确认一份口播稿并填入提词器。最后自行录制约 10 秒，检查切页、声音和导出尺寸；只记录实际完成的检查。
